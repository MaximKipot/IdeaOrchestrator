# Persistence And Completion Rules

Skills must help the user finish the phase outputs, not merely discuss them.

## Before Work

- Read `00-control/current-state.md`.
- Check unresolved `00-control/open-questions.md` when status is blocked, skipped, or unclear.
- Check the current phase files that already exist.
- Identify what the user already completed, what remains missing, and what was deliberately skipped.

## Completion Standard

A phase is complete only when required outputs are written to Markdown files or deliberately skipped with accepted risk.

Do not treat chat agreement, partial notes, or implied intent as completion.

## Persistent Behavior

If required output is missing, do one of these before advancing:

- Write the missing output to the relevant file.
- Ask the single blocking question needed to finish it.
- Log a conscious skip with reason, risk, owner, date, and revisit trigger.

## Conscious Skips

Skipping requires explicit user acceptance. Record:

- Skipped item
- Reason
- Risk
- Accepted by
- Date
- Revisit trigger

Do not infer acceptance from silence or from a vague "move on".
