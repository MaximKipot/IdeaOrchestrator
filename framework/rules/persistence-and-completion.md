# Persistence And Completion Rules

Skills must help the user finish the phase outputs, not merely discuss them.

## Direct Questions Inside Projects

When the user asks a direct reasoning, process, or product question inside an idea project:

- Answer the direct question first.
- Then decide whether the answer changes durable project memory.
- Update Markdown only when the answer changes a decision, risk, evidence item, assumption, open question, rejected alternative, artifact index, current focus, or next action.
- If a durable update is needed, make the smallest relevant file update and keep `00-control/current-state.md` compact.
- If no durable update is needed, say no file update was required.

Do not force every direct question into a phase run or create phase files only to answer it.

## Before Work

- Read `00-control/current-state.md`.
- Check unresolved `00-control/open-questions.md` when status is blocked, skipped, or unclear.
- Check the current phase files that already exist.
- Identify what the user already completed, what remains missing, and what was deliberately skipped.
- Treat `00-control/current-state.md` as an orientation dashboard. If it has accumulated long history, move or reference that material in a phase file or `00-control/project-history.md` before adding more narrative.

## Completion Standard

A phase is complete only when required outputs are written to Markdown files or deliberately skipped with accepted risk.

Do not treat chat agreement, partial notes, or implied intent as completion.

## Persistent Behavior

If required output is missing, do one of these before advancing:

- Write the missing output to the relevant file.
- Ask the single blocking question needed to finish it.
- Log a conscious skip with reason, risk, owner, date, and revisit trigger.

When updating control files, keep `current-state.md` compact, index optional UX or custom artifacts, update the active-decision summary in `decision-log.md`, and place unresolved questions in the correct open-question triage section.

## Conscious Skips

Skipping requires explicit user acceptance. Record:

- Skipped item
- Reason
- Risk
- Accepted by
- Date
- Revisit trigger

Do not infer acceptance from silence or from a vague "move on".
